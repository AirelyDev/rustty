# Where Rustty deliberately differs from Ghostty

Rustty is a full-fidelity port of Ghostty: by default it behaves exactly as Ghostty does. The
exceptions are Ghostty bugs. Where Ghostty crashes, has undefined behaviour, leaks, deadlocks, or
visibly fails to do what its own code clearly intends (for example, output silently lost because
a buffer is never flushed), Rustty does what Ghostty meant to do instead, and the difference is
listed here.

Each entry names the Ghostty behaviour, what Rustty does, and the record in
`.port/parity-closure/UPSTREAM-DEFECTS.md` (the `UD` id), which has the reference location, the
measurements, and a proposed upstream fix. The rule behind this is R13 in `.port/PORT_RULES.md`.

Entries are added by the task that makes the change.

A "safety-checked build" below is a Debug or ReleaseSafe build of Ghostty, where Zig checks
integer overflow, bounds and similar mistakes and stops the program when one fails. In a
ReleaseFast build those checks are off and the same input is undefined behaviour; where its
effect was measured, the entry says what it is.

| Area | Ghostty | Rustty | Record |
|---|---|---|---|
| Crash reporting (macOS) | The Sentry database goes to `~/Library/Caches` when `XDG_CACHE_HOME` is set, and to the XDG cache when it is not: the reverse of what its own comment says. | Uses the XDG cache when `XDG_CACHE_HOME` is set and non-empty, and `~/Library/Caches` otherwise, as the comment says. | UD21 |
| Crash reporting | Writing out a crash-report envelope whose headers are nested more than 256 levels deep crashes (the JSON writer asserts its depth limit instead of returning an error). | Returns an error instead of crashing, and still reads such an envelope. | UD182 |
| Kitty graphics | A file-medium image sent without `s=`, or a zlib payload, of exactly the 400 MiB limit is rejected, although every other size check accepts exactly the limit (the same file loads when sent with `s=`). | Accepts exactly the limit and rejects anything larger, on every path. | UD140 |
| Terminal protocols | Numbers in the glyph protocol, kitty graphics, OSC 4/104 color indices, OSC 66 text sizing, the OSC 133 exit code and OSC 9 accept Zig's `_` digit separator (`1_0` is read as 10), although Ghostty's own OSC 99 parser refuses it. | Refuses `_` in those numbers, as Ghostty's OSC 99 parser does. | UD141 |
| Version string | A development build's version reads `X.Y.Z-<branch>-+<hash>`: the branch name is sanitized before git's trailing newline is trimmed, so the newline becomes a `-` and the trim meant to remove it does nothing (a regression from upstream `ad9225a4c`). It shows in `+version`, XTVERSION, `TERM_PROGRAM_VERSION` and dist tarball names. | Trims the newline first, then sanitizes, so the version reads `X.Y.Z-<branch>+<hash>`, as it did before that commit. | UD150 |
| `+list-colors` | With `--plain`, or when its output is piped or redirected, the end of the colour list is missing: the output buffer is never flushed. | Prints the whole list. | UD22 |
| `+list-themes` | When the resources directory or the themes are missing, the "Could not find the resources directory" and "No themes found" messages are never shown (stderr is never flushed), so the command exits with status 1 and no output. | Shows both messages. | UD23 |
| Closing a terminal | Closing a terminal whose program ignores the hangup signal (or, on macOS, a login shell stuck exiting with unread output) never finishes: Ghostty waits for it forever. | Stops waiting after 10 seconds and finishes closing, leaving the program running. | UD93 |
| Opening a terminal (error path) | If opening a terminal fails after its shell has started (for example when no more threads or file descriptors can be created), the shell is stopped while nothing reads its output, which on macOS can leave it stuck and the stop waiting forever. | Reads and discards the shell's pending output before stopping it. | UD102 |
| Color queries (OSC 4, 10-19) | A sequence that queries about 25 or more colors at once (for example the whole palette) gets no answer at all, and any color changes after the queries in the same sequence are ignored: the answer overflows a small fixed buffer. | Answers every query and applies every change. | UD205 |
| Shell integration (bash) | A bash `command` that repeats `--norc` or `--noprofile` enough times (for example `bash --norc --norc --norc --norc --norc`) makes the terminal fail to open: the flags overflow a 32-byte buffer. | Opens the terminal with shell integration, passing every flag on. | UD204 |
| systemd (Linux) | A `NOTIFY_SOCKET` exactly 108 bytes long crashes Ghostty when it notifies systemd (the terminating NUL is written past the address buffer). | Reports "NOTIFY_SOCKET path is too long!", as for a longer value. | UD202 |
| systemd (Linux) | A `NOTIFY_SOCKET` naming an abstract socket (`@...`), which the code says it supports, is used as a file path named `@...`, so readiness notifications never arrive. | Connects to the abstract socket. | UD203 |
| Paths on Windows | Converting a path or argument that holds the overlong byte sequence `E0 80..9F xx` for a Windows API (for example a `PATH` entry searched for a command) crashes, in Zig's WTF-8 decoder. | Treats it as an invalid path, as it does any other malformed byte sequence. | UD201 |
| Opening URLs | When the program used to open a URL (`xdg-open`, `open`) writes a line to stderr, the thread that collects its output loops forever logging empty lines and never reaps the program. | Logs each line once and reaps the program. | UD200 |
| `+ssh-cache` | A scoped IPv6 address longer than 255 bytes given as a host (for example `--add=fe80::1%<long scope>`) crashes the command (an integer-cast trap in Zig's IPv6 parser). | Rejects the host as invalid, as it does any scoped IPv6 address. | UD160 |
| Fonts (FreeType: Linux, FreeBSD, Windows) | Asking for the name of a font whose family name (its Windows Unicode record) is too long for the buffer it is decoded into crashes, or in a ReleaseFast build writes past that buffer, because the UTF-16 decoder is not told the buffer is too small. Where Ghostty passes a 256-byte buffer (for example when it logs a synthetic bold or italic face) this starts at 86 CJK characters or 257 ASCII characters; elsewhere at 342 CJK characters. | Returns the undecoded name record instead, as Ghostty already does for a name it cannot decode. | UD190 |
| Home directory (Linux, FreeBSD) | When `HOME` is unset and the user database has no home directory, Ghostty asks the shell. That fails with an out-of-memory error when the home path is 361 bytes or longer, although the code allows 512 bytes, so `~/` paths are then not expanded. | Accepts a home path of up to 511 bytes from the shell, as the 512-byte limit intends. | UD210 |
| Temporary directory | `TMPDIR=/` (or `TMP=/`) is turned into an empty path, which Ghostty's own temporary-directory code cannot open. | Keeps `/`. An empty `TMPDIR` is an error, as in Ghostty: no temporary directory is created. | UD211 |
| Working directory (OSC 7) | In the directory a program reports with OSC 7, a malformed escape `%-0` becomes a NUL byte and `%+F` (a `+` and one hex digit) becomes a control character, although every other malformed escape is kept as written (Zig's URI decoder reads the sign as part of a number). | Decodes only `%` followed by two hex digits and keeps `%-0` and `%+F` as written. | UD230 |
| Global shortcuts (GTK) | Another program on the user's session bus can crash Ghostty by sending a malformed global-shortcuts portal signal: a `Response` without its results, or an `Activated` signal whose shortcut id is missing or of the wrong type. It must be watching the bus while a request is in flight, or know the session's handle. | Treats a `Response` without results as a request that ended unexpectedly (Ghostty's own warning), and ignores an `Activated` signal without a valid shortcut id. | UD1, UD2 |
| X11 (GTK) | If another X client destroys a Ghostty window (for example `xdotool windowclose`) and the config is then reloaded, Ghostty exits: its blur and decoration updates hit an X error that GDK treats as fatal. | Catches the X error on those updates and logs Ghostty's existing `failed to sync` error instead. GDK's own requests on such a window can still end the process (UD56). | UD3 |
| tmux control mode | A tmux control-mode block larger than 1 MiB leaves the tmux viewer running, and the next `tmux -CC` attach in the same terminal crashes Ghostty. A real tmux gets there by attaching to a pane with more than 1 MiB of history, detaching, and attaching again. | Ends the tmux session when a block is too large, as Ghostty's own comment on the limit says it should, so the next attach works. | UD6 |
| tmux control mode | A tmux notification whose pane, window or session id has 20 or more digits (for example `%output %99999999999999999999 x`) crashes Ghostty. Any program writing to the terminal can send it. | Ignores that line with Ghostty's existing "failed to match notification" warning and keeps reading. | UD7 |
| tmux control mode | A tmux layout with a pane 0 cells, or more than 65535 cells, wide or tall crashes Ghostty. | Treats it as a failed layout: the tmux viewer stops, with Ghostty's existing warning. | UD8 |
| tmux control mode | A safety-checked build crashes when a pane's history arrives after tmux has already set a scroll region for that pane (plausibly when a split is created while attaching). A release build does not crash, but writes that history over itself. | Does not crash. The history is written as in Ghostty's release build. | UD9 |
| tmux control mode | A deeply nested tmux layout overflows the stack and kills Ghostty (from about 39,000 levels in a release build; a layout may be up to 1 MiB, enough for about 116,000). | Rejects a layout nested deeper than 1000 levels, the limit tmux itself adopted; the tmux viewer stops with Ghostty's existing error. | UD10 |
| tmux control mode | A tmux pane state whose scroll region lies outside the pane crashes Ghostty at the next line feed in that pane. | Ignores such a scroll region, as Ghostty already ignores an out-of-range cursor or tab stop in the same reply. | UD11 |
| Output at exit (Linux) | When a program's last output and its exit reach the terminal together, Ghostty stops reading without reading that output, so the end of a command that prints and exits at once can be missing. (Seen in Rustty's earlier copy of this code on Linux; not yet measured in Ghostty itself.) | Reads the remaining output before it stops. Tested on macOS; the end-to-end Linux run is still pending. | UD19 |
| Custom shaders | A custom shader that reads `iSelectionForegroundColor` gets the `selection-background` color, and `iSelectionBackgroundColor` gets `selection-foreground`. | Each uniform gets the color it is named for. | UD20 |
| Terminal inspector | Keypad Page Down (NumLock off) acts as Page Up in the inspector, and keypad Begin (keypad 5, NumLock off) acts as Tab. | Keypad Page Down acts as Page Down; keypad Begin is ignored, as are other keys the inspector has no name for. | UD27 |
| libxev (event loop library) | For programs using libxev directly (Ghostty does not reach this): on the epoll backend, a positioned file read or write that fails to start, for example on a loop without a thread pool, would hand its callback a result of the wrong kind, and a callback that reads it as documented crashes. Found by reading the code. | Hands the callback a positioned read or write result, as documented. | UD50 |
| Custom shaders | With a custom shader loaded, setting `cursor-text`, `selection-foreground` or `selection-background` to `cell-foreground` or `cell-background` (which `cursor-invert-fg-bg` and `selection-invert-fg-bg` also do) crashes a safety-checked build; a release build gives the shader an undefined color. | Leaves that uniform unset, as when the option is not set. | UD57 |
| Keybindings | `goto_tab:N` with N of 2147483648 or more crashes a safety-checked build when the key is pressed; a release build goes to another tab (`goto_tab:4294967295` goes to the previous tab). | Reports the keybind as invalid, as it does for any number too large. | UD58 |
| Window size | A huge `window-width` or `window-height` (for example `window-height = 1000000000` with `window-width` set) crashes a safety-checked build at startup; a release build asks for a wrong window size. | Skips the initial size when it does not fit, as when the options are unset, and skips the minimum size the same way. | UD59 |
| Mouse reporting (library) | With UTF-8 mouse reporting on a grid at least 55,264 cells wide or tall (reachable through the library's API), an event in some of those columns or rows crashes a safety-checked build, and a release build writes invalid UTF-8. | Does not report that event, as the X10 format already does for a coordinate it cannot encode. | UD60 |
| Kitty graphics (Linux) | A program that sends a shared-memory image and shrinks the shared-memory object while Ghostty copies it kills Ghostty with SIGBUS (shown on Linux with the same system calls). | Fails the load with `EINVAL: invalid data`. | UD61 |
| Scrolling | A `scroll_page_fractional` keybind with a huge value (for example `scroll_page_fractional:1e30`) crashes a safety-checked build when used, and so does an embedder passing an infinite or huge scroll offset. | Scrolls as far as it can for a huge fraction, and ignores a non-finite or huge scroll offset. | UD62 |
| Library on 32-bit targets | On 32-bit targets such as wasm32, setting a Kitty image storage limit above 4 GiB through the library's C API aborts the host program in a safety-checked build, and sets a limit of 0 in a release build. | Treats such a limit as no practical limit. | UD63 |
| Terminal snapshots (library) | Decoding a malformed snapshot whose page header declares a very large capacity crashes the program using the library (a safety-check failure, or SIGBUS in a release build). | Rejects it as malformed input. | UD64 |
| Terminal snapshots (library) | Decoding a snapshot page in which more than 65,534 cells share one style crashes a safety-checked build, and leaves a live style with a zero reference count in a release build. | Stores the extra cells with the default style, as the decoder already does for a style it cannot map. | UD65 |
| Terminal snapshots (library) | A malformed snapshot record that declares a string far longer than itself makes the decoder ask for 4 GiB per string. Where the system refuses, the error is reported as out of memory (or, for the cursor's hyperlink, the hyperlink is silently dropped) instead of as malformed input. | Rejects the length as malformed input before allocating. | UD66 |
| Child exit (macOS, FreeBSD) | A command that exits before Ghostty starts watching it makes the watch fail (measured on macOS), and Ghostty treats that failure as impossible: a safety-checked build crashes. | Reports the child as exited, with status 0. On FreeBSD a command that fails at once is therefore not reported as an abnormal exit (by reasoning; no FreeBSD host was measured). | UD67 |
| New tabs, splits and windows (macOS) | Every new tab, split or window that inherits the working directory leaks a copy of the directory path. | Frees it. | UD68 |
| Keyboard layouts (macOS) | If macOS returns no keyboard layout, or one without Unicode layout data, when the layout changes, Ghostty keeps using a layout it has already released, and releases it again at exit; at startup the same failure leaks the layout. Found by reading; not reproduced. | Keeps the previous layout when a reload fails, and releases each layout exactly once. | UD69 |
| Rendering (macOS) | A window that appears or resizes while its renderer is starting can run its draw callback without a renderer and crash. Found by reading; not reproduced. | Installs the renderer before the callback, and skips a callback that has none. | UD70 |
| Window padding | A huge `window-padding-x` or `window-padding-y` (for example 2147483648) crashes a safety-checked build at startup; in a release build it wraps around to no padding. After a reload that sets such a padding, a display-scale change can also make the input-method position and the custom-shader cursor overflow the same way, until the terminal is resized (found by reading). | Treats the padding as larger than the window: the terminal keeps its one-cell minimum, and Rustty warns as it does for any unreasonable padding. | UD71, UD76 |
| `+list-themes`, `+boo` (mouse) | Mouse input with both wheel bits set (for example `ESC [ < 192 ; 1 ; 1 M`), or an old-style mouse report with a byte below 32, crashes a safety-checked build. | Ignores that mouse event. | UD72 |
| Renderer (Linux) | Losing focus just as the cursor-blink timer fires can crash a safety-checked build on Linux with io_uring. Found by reading; not reproduced in 170,000 attempts. | Carries on: the blink timer is stopped, or keeps ticking harmlessly while unfocused. | UD73 |
| `+list-themes`, `+boo` (resize) | Resizing the terminal as the TUI starts can deadlock it: its resize signal handler takes a lock, which blocks forever if the interrupted thread holds it. Found by reading. | The signal handler only writes to a pipe; the resize is handled on an ordinary thread. | UD74 |
| Renderer (Linux) | On Linux without io_uring (the epoll fallback), a failure to register the renderer's stop signal, for example when the per-user epoll watch limit runs out at that moment, crashes a safety-checked build. Found by reading. | Retries the registration, as Ghostty already does for the renderer's wake-up signal. | UD75 |
| Very wide terminals (library) | On a terminal 47,932 or more columns wide on macOS arm64, or 46,908 on Linux aarch64 (in practice only through the library's C API), styled output crashes a safety-checked build and corrupts style reference counts in a release build. | Keeps such a style alive instead of counting past the limit. | UD80 |
| Input methods (GTK) | An input method that commits exactly 128 bytes of text during a keypress crashes a safety-checked build; a release build drops the text. | Accepts the 128-byte commit. | UD90 |
| Global keybinds (Wayland) | A `global:` keybind on a key GTK has no keysym for (for example `global:audio_volume_up=...`) crashes a safety-checked build when the hotkeys are registered, on a compositor that offers the Vicinae hotkey protocol. | Skips that keybind with Ghostty's existing "failed to request hotkey" warning; the others are still registered. | UD91 |
| Fonts | A font whose `SVG ` table lists no documents, or more than fit in the table, makes Ghostty read past the table (a crash in a safety-checked build). | Rejects the table as truncated. | UD92 |

| Quick terminal (Wayland) | `quick-terminal-size = inf%`, or a pixel size above 2147483647, crashes a safety-checked build. | Uses the values Ghostty's release build uses; a pixel size too large for GTK is ignored with GTK's warning, as there. | UD96 |

| `+crash-report` | A crash file whose modification time is more than about 584 years old (Linux tmpfs and btrfs can store one) crashes a safety-checked build of `+crash-report`; a release build shows a wrong age. | Shows the largest age it can represent. | UD99 |

| Closing windows (GTK) | Closing a window within half a second of closing its tab overview can run a timer on the freed window. Found by reading. | Removes the timer when the window goes away. | UD103 |

| `+list-themes`, `+boo` (keyboard) | Key text queued faster than the TUI handles it (more than 8 KiB) can be read after it has been overwritten. Found by reading. | Copies each key's text into its event. | UD107 |

| Fonts (macOS) | Each time Ghostty asks for the name of a font loaded from memory (its built-in fonts, for example in `+show-face`), it leaks a copy of the name. | Keeps one copy per font and releases it with the font. | UD110 |

| Opening a terminal (error path) | If creating a terminal fails partway, its font grid is never released, and quitting then crashes a safety-checked build. | Releases it. | UD115 |
