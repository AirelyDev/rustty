# WS16 — GTK X11 Winproto Arm Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Complete the GTK X11 window-protocol arm (`crates/rustty-apprt/src/gtk/winproto/x11.rs`) to full R1 fidelity with the oracle `src/apprt/gtk/winproto/x11.zig` — closing the three sub-deferrals that arm still carries (XKB extension init, the `eventMods` XKB modifier peek, and the `WINDOWID` subprocess-env hook) — and prove the whole arm live on the VM under `GDK_BACKEND=x11`, without regressing the Wayland arm or the default build.

**Architecture:** The arm is a `#[cfg(feature = "x11")]` variant of the `winproto::App` / `winproto::Window` enums (`winproto.rs`), selected by `App::init`'s ordered fall-through (`noop` → `wayland` → `x11`, first `Some` wins). WS16 adds three faithful hunks to the existing arm: (1) `App::init` gains the XKB `XkbQueryExtension` + `XkbSelectEventDetails` initialization and stores `base_event_code`; (2) `App::event_mods` peeks the X event queue for a pending `XkbStateNotify` and derives `Mods` from `lookup_mods`; (3) `Window::add_subprocess_env` publishes `WINDOWID`, which requires a new `winproto::Window::add_subprocess_env` dispatch method (no-op on the `noop`/`wayland` arms, exactly as the oracle), a `Window::winproto_mut()` accessor on the GTK `Window` class (oracle: `window.zig:386-388` `winproto()`), and the `default_termio_env` call site in `class/surface.rs` (oracle: `surface.zig:1629-1638`). Verification is a live GTK app launched under XWayland with `GDK_BACKEND=x11`, inspected with `xprop`/`xdotool`.

**Tech Stack:** Rust 1.93.1 (pinned), gtk4-rs 0.11 stack, `gdk4-x11` 0.11.4 (feature `xlib`, which re-exports `x11-dl` 2.21 as `gdk4_x11::x11`), Fedora 44 aarch64 VM (`ssh rvm`) running a live GNOME/mutter Wayland session with rootless `Xwayland :0`, oracle git repo at `/Users/gael/projects/ghostty` (working tree pinned at `4749c4e93`).

### What `GDK_BACKEND=x11` under rootless XWayland DOES prove

- The GDK display really is a `GdkX11Display`, so `App::init`'s downcast hinge fires
  and the winproto union lands on `Protocol::X11` (not the wayland/noop fallback).
- `XkbQueryExtension` / `XkbSelectEventDetails` succeed against a real X server
  (XWayland implements XKB fully) and yield a non-zero `base_event_code`.
- Real X windows exist with real XIDs, so `WM_CLASS`, `_MOTIF_WM_HINTS`,
  `_KDE_NET_WM_BLUR_BEHIND_REGION`, and `WM_HINTS`'s urgency flag are all written to
  a real X server and readable with `xprop`. mutter is the window manager for
  XWayland clients and DOES honor `_MOTIF_WM_HINTS` decorations, so the SSD/CSD
  toggle is observable, not just the property write.
- `WINDOWID` in the child environment is a real, resolvable XID (`xprop -id $WINDOWID`
  round-trips).

### What it does NOT prove

- **No KWin ⇒ no visible blur.** `_KDE_NET_WM_BLUR_BEHIND_REGION` is a KDE protocol;
  under mutter only the *property write* is verifiable, never the visual effect.
  (Same limitation the Wayland arm already carries as VERIFICATION_DEBT V3.)
- **Not a login-session X11 run.** Startup paths that differ between "GTK app told to
  use the X11 backend inside a Wayland session" and "GTK app in a native X11 session"
  (e.g. XSETTINGS/xrdb-provided scale factors, XDG session-type-dependent portal
  behavior) are untested. Nothing in `winproto/x11.zig` reads those, but the claim
  must be scoped honestly.
- **XKB event ordering under XWayland** is XWayland's synthesis of Wayland keyboard
  events, not a native X keyboard driver. The `eventMods` peek is verified to fire
  and decode correctly, but a native-X-server keymap edge (e.g. exotic XKB options)
  is out of reach here.

Task 8 records both gaps as a new VERIFICATION_DEBT row rather than claiming more
than was run.

    /// state-update event and derives the keyboard modifiers from it. This is
    /// necessary because the standard GTK X11 API (and X11 generally) does not

    /// own event — so pressing e.g. Shift does not show `shift` set.

    /// ([`super::App::event_mods`]) then falls back to the plain GDK modifier state
    /// via `key::translate_mods` (`winproto.zig:62`).

    /// `widget/gtk/nsGtkKeyUtils.cpp` (`x11.zig:132-133`).
    #[must_use]
    pub fn event_mods(
        &self,
        _device: Option<&gdk4::Device>,
        _gtk_mods: gdk4::ModifierType,

        // (`x11.zig:134-137`). This guard is load-bearing: XPeekEvent BLOCKS when
        // the queue is empty.

            return None;

        // `var nextEvent: XEvent = undefined; _ = XPeekEvent(display, &nextEvent)`
        // (`x11.zig:139-140`). PEEK, not next: the event stays queued for GDK.
        let mut next_event = std::mem::MaybeUninit::<xlib::XEvent>::uninit();
        unsafe { (self.xlib.XPeekEvent)(self.display, next_event.as_mut_ptr()) };
        let next_event = unsafe { next_event.assume_init() };

        // `if (nextEvent.type != self.base_event_code) return null` (`x11.zig:141`).
        if unsafe { next_event.type_ } != self.base_event_code {
            return None;
        }

        // `const xkb_event: *XkbEvent = @ptrCast(&nextEvent); if
        // (xkb_event.any.xkb_type != XkbStateNotify) return null` (`x11.zig:143-144`).
        // `xlib::XEvent` is a union whose `pad: [c_long; 24]` (192 bytes on LP64) is
        // the standard Xlib event buffer, which is >= every Xkb*Event — the same
        // reinterpretation the reference does with `@ptrCast`.
        let any: xlib::XkbAnyEvent = unsafe {
            std::ptr::read_unaligned(std::ptr::from_ref(&next_event).cast::<xlib::XkbAnyEvent>())
        };
        if any.xkb_type != xlib::XkbStateNotify {
            return None;
        }

        // `const xkb_state_notify_event: *XkbStateNotifyEvent = @ptrCast(xkb_event);
        // const lookup_mods = xkb_state_notify_event.lookup_mods` (`x11.zig:146-148`).
        let state: xlib::XkbStateNotifyEvent = unsafe {
            std::ptr::read_unaligned(
                std::ptr::from_ref(&next_event).cast::<xlib::XkbStateNotifyEvent>(),
            )
        };
        let lookup_mods = c_uint::from(state.lookup_mods);

        // `log.debug("X11: found extra XkbStateNotify event w/lookup_mods: {b}")`
        // (`x11.zig:151`).
        eprintln!(

        );

        // `x11.zig:149,152-158` — the XKB mask -> `input.Mods` mapping.
        let mut mods = rustty_vt::input::key_mods::Mods::default();
        if lookup_mods & xlib::ShiftMask != 0 {
            mods.shift = true;
        }
        if lookup_mods & xlib::ControlMask != 0 {
            mods.ctrl = true;
        }

            mods.alt = true;
        }
        if lookup_mods & xlib::Mod4Mask != 0 {
            mods.super_ = true;
        }
        if lookup_mods & xlib::LockMask != 0 {

    }
