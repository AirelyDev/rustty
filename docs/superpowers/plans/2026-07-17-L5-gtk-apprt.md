# L5 — Native GTK4/libadwaita apprt backend Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Port `src/apprt/gtk/**` (55 `.zig` = 22,045 loc + 21 `.blp` + 4 `.css`) into a **native Rust gtk4-rs apprt backend** — a new `gtk` module in `crates/rustty-apprt` (sibling of `embedded`/`none`) that `impl`s the apprt-api seam (`App`/`Surface`/`CoreSurfaceHandle`, `crates/rustty-apprt-api/src/seam.rs:54,69,124`) against GObject widgets, wired into the GUI launch leaf at `crates/rustty/src/main_rustty.rs:292` for `Runtime::Gtk`. End state: `rustty` launches an `AdwApplicationWindow`, runs a live shell, renders via L4's OpenGL backend, and takes keyboard/mouse input on Linux.

**Architecture:** Mirror ghostty exactly (AD-1): GTK is a native backend, not an app over the C ABI — `rustty-apprt-c` is untouched. The tier's one structural fact (PREPORT_GTK §0): every user-visible class is a GObject subclass authored with ghostty's `class.zig::Common(Self, Private)` helper (`class.zig:16-363`), 25 `gobject.ext.defineClass` sites across 22 files. Rust re-expresses each in the gtk4-rs idiom triad — `#[glib::object_subclass]` + `CompositeTemplate` + `glib::Properties` — with `Private` → the `ObjectSubclass` impl struct, `bindTemplateChildPrivate` → `#[template_child]`, `bindTemplateCallback` → `#[template_callback]`, `defineVirtualMethod` → the `*Impl` trait overrides. The two shims (`App.zig` 96 loc, `Surface.zig` 105 loc) become the `apprt_api` trait impls; `class/application.zig` (2960) and `class/surface.zig` (4127) carry the lifecycle and the render contract. The `.blp`/`.css` are copied **verbatim** and compiled by a `build.rs` pipeline (blueprint-compiler → gresource XML → glib-compile-resources → `cc` → `gio::Resource::register` at class-init). The event loop is **hand-rolled**, not `ApplicationExt::run` (AD-7): `acquire → register → activate → while(running){ MainContext::iteration(blocking); core_app.tick(rt_app); check-quit }` (`application.zig:477-592`), with `glib::MainContext::wakeup(None)` as the libghostty→GTK bridge (`application.zig:1286-1289`).

**Tech Stack:** Rust; gtk4-rs from crates.io (AD-2) — `glib`, `gobject`(via glib), `gio`, `gdk4`, `gtk4`, `libadwaita`, later `gdk4-wayland` — built against system pkg-config gtk4 4.22 / libadwaita 1.9. Build-time: `blueprint-compiler` 0.20, `glib-compile-resources`, `msgfmt`, `cc`. Wayland: `wayland-client` + `wayland-protocols`(+wlr/kde) + `gtk4-layer-shell` (L5.4). No new `-sys` crate for GTK itself. Reference oracle = ghostty pinned `4749c4e9` at `/home/gael/projects/ghostty` (read-only); every `file:line` below resolves against it.

**Deps (hard):** **L1** (`rustty-xev` epoll/io_uring/Dynamic — every `Surface::init` spawns a pty + io thread + renderer thread over the loop), **L4** (renderer OpenGL backend — `gl_render` calls `renderer.draw_frame(true)`), **L3** (fontconfig discovery — a surface without fonts can't shape a cell). L5.0/L5.1 scaffolding can proceed against `winproto::noop` before L4 lands; the FIRST-LIGHT KAT (Task 20) is the first point that hard-requires all three.
