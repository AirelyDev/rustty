rustty — the Atlas.Wasm texture rendered through WebGL2

This page is the wasm consumer. Upstream ghostty's src/renderer/WebGL.zig is a two-line placeholder — a doc comment and pub const WebGL = @This();, with no fields, methods, shaders or draw path — so there is no browser renderer to port. libghostty's wasm model is that the consumer renders itself, which is exactly what happens here: rustty_wasm.wasm (the port of main_wasm.zig) owns the texture atlas through Atlas.Wasm's C ABI, and the page below uploads that atlas as an R8 texture and draws one quad per glyph with WebGL2.

Serve it over HTTP from the repository root — fetch() of a .wasm does not work from file://: 

.port/tools/build-main-wasm.sh --release
python3 -m http.server 8731 --bind 127.0.0.1
open http://127.0.0.1:8731/example/wasm-webgl/index.html

Everything below is asserted, not admired. The per-cell ink counts read back with gl.readPixels must equal an expectation computed on the CPU from the atlas bytes the wasm module holds (never from a JS copy of what was written), the third cell column must be exactly zero, and two negative controls must FAIL on every run: NC1 shifts each glyph's atlas offset by 3px, NC2 makes the fragment shader emit black. The same assertion body runs headlessly in .port/tools/gates/ws14_webgl_browser_gate.sh.
