# Phase-4 non-ports (deliberate, evidenced — the `quirks_memset` class)

Rows here are NOT deferrals: each records a range item with a written argument that a
faithful port would be wrong or meaningless in Rust, plus the condition that would reopen it.

| item | upstream | verdict | argument | reopens if |
|---|---|---|---|---|
| `src/lib/TinyIo.zig` (1,522) + the `82df79ec8` module-export rider | NEW file; used by the streaming C APIs as a lightweight blocking `std.Io` implementation | **NON-PORT (CONFIRMED by W5 Bundle S, 2026-08-25)** | TinyIo exists to satisfy Zig 0.16's `std.Io` VTable interface (~60 fn pointers) so lib code avoids `std.Io.Threaded`'s TLS/vtable bloat — a Zig-stdlib/linker concern. rustty has NO `std.Io` abstraction anywhere (rustty-zigstd models only the concrete types actually used); the Rust streaming C APIs read/write via `std::io`/`std::fs` directly. Porting it would invent the entire `std.Io` interface + ~20 raw POSIX externs into a leaf crate with ZERO consumers (R9 density increase, dead code). Its ~20 tests drive Zig stdlib machinery (`testing.tmpDir`, `File.Reader.appendRemaining`, `Io.Mutex`) with no Rust counterpart. **Bundle S re-read (per the reopen trigger): no blocking-IO seam materialized.** The Rust snapshot codec's own byte traits (`rustty_vt::snapshot::io::{Reader,Writer}`, made `pub` for the C tier) ARE the whole seam: `crates/rustty-vt-c/src/io.rs` adapts the `RusttyReader`/`RusttyWriter` callback pairs to those traits with the reference's observable contract intact (one-byte peek boundary, direct bulk reads, 4 KiB buffering, sticky failure/EOF, offset accounting). The reference's TinyIo consumers on this surface — `terminal_c.Io` (the per-terminal owner) and `snapshot.decode`'s `io` argument — are structurally N/A because the Rust codec signatures never took an `io` parameter (`codec.rs` PORT NOTE); `terminal.rs`'s `Io` PORT NOTE marks the type N/A at the wrapper. No filesystem/syscall path exists anywhere in the streaming C APIs (kitty temp-file media go through `std::fs` in their own tier). | A future upstream consumer threads `std.Io` into an API whose Rust port genuinely needs pluggable blocking IO (not just byte callbacks); that port must re-read this row again. |
