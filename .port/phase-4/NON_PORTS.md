Porting it would invent the entire `std.Io` interface + ~20 raw POSIX externs into a leaf crate with ZERO consumers (R9 density increase, dead code). Its ~20 tests drive Zig stdlib machinery (`testing.tmpDir`, `File.Reader.appendRemaining`, `Io.Mutex`) with no Rust counterpart. **Bundle S re-read (per the reopen trigger): no blocking-IO seam materialized.** The Rust snapshot codec's own byte traits (`rustty_vt::snapshot::io::{Reader,Writer}`, made `pub` for the C tier) ARE the whole seam: `crates/rustty-vt-c/src/io.rs` adapts the `RusttyReader`/`RusttyWriter` callback pairs to those traits with the reference's observable contract intact (one-byte peek boundary, direct bulk reads, 4 KiB buffering, sticky failure/EOF, offset accounting). The reference's TinyIo consumers on this surface — `terminal_c.Io` (the per-terminal owner) and `snapshot.decode`'s `io` argument — are structurally N/A because the Rust codec signatures never took an `io` parameter (`codec.rs` PORT NOTE); `terminal.rs`'s `Io` PORT NOTE marks the type N/A at the wrapper. No filesystem/syscall path exists anywhere in the streaming C APIs (kitty temp-file media go through `std::fs` in their own tier). **Phase 7 re-read (P7-W0 T4, DECISIONS R5, R3 §3.1):** `f6cb8312b` ("tinyio: implement a Windows version and use it in the C API") splits TinyIo into `src/lib/tinyio/posix.zig` (the POSIX syscalls), `src/lib/tinyio/windows.zig` (a new ntdll/kernel32 arm, 2 tests) and `src/lib/tinyio/test.zig` (the 21 shared tests, moved out of `TinyIo.zig`), and makes `terminal_c.Io` a stateless `lib.TinyIo` on every target (`src/terminal/c/terminal.zig:54-59` at 12752b2ac) instead of `std.Io.Threaded` on Windows. That changes which `Io` the existing consumers get and adds none, so the trigger did not fire; the verdict and argument above cover the three new files, their 23 tests and their `pub fn`s. The `src/os/windows.zig` constants and externs added for the Windows arm have no Rust caller while TinyIo is a non-port. | A future upstream consumer threads `std.Io` into an API whose Rust port genuinely needs pluggable blocking IO (not just byte callbacks); that port must re-read this row again. |

| `src/apprt/gtk/class/config.zig` `pub fn getMut` (`:94-100`) | returns `*CoreConfig` into the GObject's private data — "usually NOT recommended because any changes to the config won't be propagated" | **NON-PORT (parity tail S-8d, 2026-09-24, N281)** | The Rust `Config` GObject (`crates/rustty-apprt/src/gtk/class/config.rs`) is a refcounted, freely cloned handle; `get` hands out `&CoreConfig` from a set-once `OnceCell` in the instance private. A `&mut CoreConfig` from `&self` would alias every other handle's shared borrow (unsound), so a faithful `getMut` needs the storage turned into a `RefCell` and `get` into a guard-returning borrow — a signature change for every `get` caller, for a function that has **no caller** in the reference GTK tree at the pin (whole-tree grep: the definition only) and none in rustty. **Alternative considered and declined (S-8e review):** a projection of the reference's raw `*CoreConfig`, `unsafe fn get_mut(&self) -> *mut CoreConfig` over `UnsafeCell<CoreConfig>` storage, would keep `get`'s signature and push the reference's "if you know what you're doing" obligation onto the caller. It was declined because it adds an `unsafe` aliasing contract (every outstanding `&CoreConfig` from `get` must be dead before a write through the pointer, which no caller could check) to buy a function nothing calls — ADJUDICATION S51-F1's unreachable class; it is the shape to use if a caller ever appears. Its three distinctive reference doc lines are declared in `.port/parity-closure/COMMENT-NOT-CARRIED.tsv` (G3b NOT-CARRIED). | A reference or rustty caller of `getMut` appears; then port it over `RefCell` storage and update `get`'s callers. |
